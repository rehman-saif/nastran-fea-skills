# Documentation index

What is in this skill, and the order to consult it.

## Layout

```
apex-scripting/
  SKILL.md
  references/     hand-written guides — read these first
  api/            generated API reference — the authority on what exists
    functions-index.md    all 989 module functions, one line each
    methods-index.md      all 5108 class methods, one line each, as module.Class.method
    enums.md              all 237 enums with their exact members
    classes.md            all 733 classes, with base classes and briefs
    modules/<module>.md   enums + module function signatures
    classes/<module>.md   class properties and full method signatures
  assets/         templates to copy from
  tools/          generation and validation scripts
```

The package is self-contained for use: everything needed to answer a question
ships as markdown. Regenerating `api/` needs the Apex documentation archive. See
[../api/README.md](../api/README.md) for regeneration.

## Lookup order

1. **[cheat-sheet.md](cheat-sheet.md)** — API conventions in brief. Read before
   writing any Apex code. [scripting-model.md](scripting-model.md) is the full
   version.
2. **[fe-vocabulary.md](fe-vocabulary.md)** — from an FE term (glue, RBE2, SPC,
   PSOLID, subcase) to the Apex call.
3. **[module-selection.md](module-selection.md)** — narrow the task to a module.
4. **`api/functions-index.md`** — grep for the verb or noun to find the exact
   function and its module.
5. **`api/methods-index.md`** — grep for a class method; scenario, subcase,
   case control and interaction work is all methods.
6. **`api/modules/<module>.md`** — the signature, argument names and defaults.
7. **`api/enums.md`** — confirm every enum member.
8. **`api/classes/<module>.md`** — entity properties and methods.
9. **[patterns-and-recipes.md](patterns-and-recipes.md)** — verified idioms to
   build from.
10. Per-parameter documentation is inline under each signature in
   `api/modules/` and `api/classes/` — there is no separate source to drill into.

## Provenance and version

`api/` is generated by `tools/gen_api.py` from the Apex Doxygen XML for
**Iberian Lynx FP2** (generated May 2024). It is authoritative for what exists,
for signatures, and for per-argument documentation, except where a stamped
runtime note says Apex 2024.1 behaves differently.

The concept, custom tool and GUI SDK material in `references/` comes from the
Apex product documentation, which describes **Apex 2021.4 / Python 3.8.2**.
Tool authoring structure and the GUI SDK have been stable across these releases,
but see pitfall 14 in [pitfalls.md](pitfalls.md) when a user is on a specific
version.

The full original 1.76 GB documentation set is **not** bundled and is not
needed. `api/` covers the scripting API in full;
`references/` carries the distilled concepts and the custom tool material.

## Tools

| Script | Does |
|---|---|
| `tools/gen_api.py` | regenerate `api/` from an Apex `ScriptingXML` folder |
| `tools/runtime_overrides.json` | hand-kept runtime behaviour (calls that raise or fail silently in Apex 2024.1), stamped into `api/` by `gen_api.py` |
| `tools/validate_references.py` | check every `apex.*` name in the prose, templates and overrides still exists |

Both derive their paths from their own location, so the skill works from
any directory.
